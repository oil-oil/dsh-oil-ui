# 轻量 UX 走查（UX 子 Agent 专用）

只通过真实页面或可操作的高保真原型观察，不读页面源码、开发工具、原始任务或设计说明，不猜测制作组别。没有可操作环境时明确改报“静态 UX 走查”。

1. 先看页面，再用自己的话写下：这是什么产品、谁会用、最可能来完成什么。不要等待主 Agent 给任务，不把界面上的功能清单逐项当作任务清单。
2. 从可见内容里选一条你认为最重要的路径，从真实入口走到可观察结果。每一步记“看到什么 → 为什么这样操作 → 实际发生什么”；不知道下一步时先按当前理解尝试，不故意表现迷路，也不替产品找补。
3. 标记**卡住**（走不下去）、**走错**（动作结果与预期不符，需要退回）、**犹豫**（需要猜或停下来比较）。再记操作后是否知道正在等待、已经完成或失败，以及反馈是否出现在动作附近。不要用操作耗时推断真人效率。
4. 只报告影响主要任务的关键问题，最多 3 条。每条分开写：**观察到的事实**（位置、操作、结果和截图/状态证据）、**原因推断**、**建议达到的结果**。事实与工具限制分不清时标为待复现，不断言是产品缺陷。

输出先写产品理解、自己选择的任务、完成 / 部分完成 / 未完成及实际路径，再写关键问题和没验证什么。声音、触觉和真机手感没法验证时不当作通过。不打审美分，不声称代表真实用户，不给真实用户成功率、满意度或耗时结论。
