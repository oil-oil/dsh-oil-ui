# 任务工作区

把过程文件和正式交付分开。`.oil-ui` 是项目里的本地工作区，不是交付目录，也不是另一套设计规范。

## 优先级与边界

- 用户指定的输出路径和项目已有约定优先。项目已经规定 `_work/`、`shots/` 或其他过程目录时沿用，不另建 `.oil-ui`，也不迁移旧文件。
- 没有约定时，从项目根目录使用 `.oil-ui/<任务名>`。任务名用简短、可辨认的名称；同名目录属于别的任务时加后缀，不覆盖。
- 真实代码、正式测试、最终文档和线上引用的资产仍写用户项目。页面、构建配置、样式和脚本不得引用 `.oil-ui`。
- 不把凭据、未脱敏的用户数据或令牌写进工作区。不自动清理历史任务；删除、迁移和对外上传仍需授权。

## 开始任务

先读项目的 `AGENTS.md`、`DESIGN.md` 或同类规范，再决定工作目录。没有这些文件不影响开始。

`.oil-ui` 已存在但不是目录，或者它是指向别处的符号链接时，不往里写，说明冲突并由用户决定。已是普通目录时复用，不清空。每个任务使用独立子目录，继续同一任务时才复用该子目录。

`.oil-ui/.gitignore` 不存在时写入：

```gitignore
*
!.gitignore
```

它只忽略过程文件，不修改项目根目录的 `.gitignore`。已有这个文件但内容不同时保留原文，并告诉用户过程文件可能出现在 Git 状态里。需要提交的证据或文档应明确放到项目正式位置，不改变忽略规则。

## 过程文件放哪

按实际需要创建子目录，不为形式完整创建空目录：

- `explore/`：候选方案、调研、未确认的设计草稿和临时小样。
- `assets/`：原始素材、中间变体和素材缓存。
- `shots/`：截图、录屏和评审证据。
- `logs/`：命令日志和临时输出。

需要长期保存的正式测试、设计规范和交付文档不藏在这里。进行中的迁移状态留在任务目录；已确认和已验收的结果才写回项目规范。

## 从任务目录运行工具

把 `.oil-ui/<任务名>` 作为命令的工作目录，输入的项目文件使用明确路径。现有默认输出就会留在任务目录，不需要改写工具默认值。显式 `--out`、`--dir`、`--cache` 和其他输出参数始终优先，不重新解释。

```text
node <skill>/scripts/shoot.mjs <项目根>/path/page.html --out shots
node <skill>/scripts/curate-media.mjs search "<关键词>" --dir assets
<python> <skill>/scripts/build_explorer.py explore
```

候选目录在 `explore/` 时，对比页也默认生成在那里。工具选项见 [工具](tools.md)。

生图或图片处理的最终结果要成为页面资产时，直接输出到项目正式资产目录，例如：

```text
node <skill>/scripts/oiloil-image.mjs image "<说明>" --out <项目根>/assets/generated.webp
node <skill>/scripts/prep-image.mjs <项目根>/originals --out <项目根>/assets/web
```

中间原图可以留在工作区，但最终 HTML 只能引用项目正式位置里的文件。

## 存量项目续作

- 先核对 `DESIGN.md` 里的样板页面、共享变量和组件路径仍存在，且没有已经换成另一套规范。失效条目标为待确认，不静默当成现行标准。
- 用户确认的方向才写入 `DESIGN.md`；未确认的方向和无人值守时的草稿留在工作区。
- 已验收的样板页面和待迁移范围写进项目规范，进行中的状态留在工作区。取值仍以共享代码为准，不复制一份会逐渐过时的样式值。
- 项目已有文档结构时只补充，不另建平行规范。是否给 `AGENTS.md`、`CLAUDE.md` 加入口仍由用户决定。

## 交付检查与停止

交付前核对最终改动，不只看命令是否成功：

- `git status` 和最终 diff 中只有正式交付、必要的规范更新和用户要求的文件。
- 正式代码和页面没有 `.oil-ui` 引用，所引用的资产都存在于项目正式位置。
- 项目根目录没有意外新增的候选、截图或缓存；旧文件没有被移动或删除。
- 交付说明给出正式文件和工作区证据的位置，并运行项目相应检查。

现有约定和工具已经能完成时，不新增目录管理程序。只有真实任务反复出现建错目录、覆盖任务或误交付时，才把初始化或检查做成脚本。
